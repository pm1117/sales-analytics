# 有料化前 法務確認チェックリスト（弁護士相談用）

- ステータス: ドラフト v0.1（2026-07-04）
- 目的: 本プロダクト（公開Web収集＋Claudeによるリサーチカルテ生成・**有料提供**）の商用化前に、弁護士へ確認すべき論点を整理する。
- 関連: `docs/collection-cache-design.md` §9-4 / `docs/product-concept.md` §5・§7
- 注意: 本書は社内整理用であり法的助言ではない。IT・知財に強い弁護士のレビューを前提とする。

現状（PoC）は「同一ドメイン10〜20秒間隔・並列1本・robots.txt尊重」のマナーのみを遵守して収集する段階。以下は**有料化＝商用提供に踏み切る前**に潰す論点。

---

## 1. 著作権法 第30条の4（情報解析の例外）

- [ ] **「享受目的の併存」問題**: 収集・埋め込み・RAG等の“中間コピー”は情報解析として30条の4に乗る想定。しかし最終成果物（カルテ）は人間が読む＝表現の享受にあたり得る。**出力段階が30条の4の射程外になるリスク**の評価。（文化庁「AIと著作権に関する考え方」2024 を踏まえて）
- [ ] **出力の作り込みで足りるか**: 「事実ベースの要約・自分の言葉・逐語転載なし・原文はリンク参照」で享受目的を回避できるか。どこまでの引用・要約なら安全圏か。
- [ ] **引用（32条）の要件**: カルテ内で原文を引く場合、明瞭区別性・主従関係・必然性・出典明示を満たす設計になっているか。許容される分量の目安。
- [ ] **「著作権者の利益を不当に害する」ただし書き**: 有料提供・原文に近い再配信・相手の有料データ事業との競合が、この除外に該当しないか。

## 2. 利用規約（契約）とのオーバーライド問題

- [ ] **契約 vs 権利制限**: サイト規約の「複製禁止」が30条の4の権利制限を上書きできるか（オーバーライド問題は未決着）。契約違反として損害賠償・差止のリスク評価。
- [ ] **同意の成立**: クリック同意なしの単なる閲覧・スクレイピングで規約への同意が成立するか。プロダクトとして規約NGサイトをどう扱うべきか（一律除外 / 個別判断）。
- [ ] **API/フィード提供時の条件**: 公式RSS/APIを使う場合の各社利用条件（商用利用・再配信の可否）。

## 3. 個人情報保護法（キーパーソン等の公開情報）

- [ ] **公開情報の収集・保存・利用**: 役職・登壇歴・SNS公開発信などの公開個人情報を収集・DB保存・カルテ表示することの適法性（利用目的の特定・通知/公表）。
- [ ] **第三者提供**: カルテを顧客（営業担当）に提供することが「第三者提供」に当たるか、本人同意・オプトアウトの要否。
- [ ] **要配慮個人情報**の混入防止と、開示・訂正・削除請求への対応フロー。
- [ ] **保存期間・削除ポリシー**（収集データの保持と、本人・権利者からの削除要請）。

## 4. その他の関連法・リスク

- [ ] **不正競争防止法**: 相手が「限定提供データ」として管理するDBのスクレイピングに該当しないか。
- [ ] **業務妨害（偽計業務妨害）**: 過度なアクセス負荷の刑事リスク。現行のレート制御（同一ドメイン10〜20秒・並列1・robots尊重）で十分か、追加すべき自主基準。
- [ ] **不正アクセス禁止法**: 認証回避を伴う取得は行わない前提の確認。
- [ ] **アンチボット対策サイトの回避手段**: マネージドAPIフォールバック（opt-in・従量ユーザー負担）を使う場合の規約・法務。
- [ ] **サイト別リスク分類**: ①自社/顧客サイト（同意あり）②一般企業サイト③報道メディア④有料DB事業者⑤SNS ― それぞれで許容範囲が異なる。特に③④⑤は要慎重。

## 5. サービス提供者としての設計・免責

- [ ] **自社サービス利用規約**: 生成物（カルテ）の正確性・ハルシネーションに関する免責、ユーザーの利用範囲、二次利用の制限。
- [ ] **出典表示義務**: 全記述への出典リンク付与を「機能」だけでなく規約上も担保すべきか。
- [ ] **オプトアウト対応**: 収集対象企業からの「掲載・収集停止」要請を受け付ける窓口・手順（レピュテーション対策）。
- [ ] **収集データの再配信禁止**の技術的・契約的担保（生Markdownをそのまま外部提供しない）。

---

## 現状の設計で既に入れている担保（弁護士へ提示する事実）

- 収集時は LLM 構造化せず生 Markdown を蓄積（情報解析目的の中間コピーとして整理）。`fetch_log.legal_basis='jp_copyright_art30_4'` を記録。
- 全取得を `fetch_log` に記録（監査・エビデンス）。
- robots.txt を尊重し、不許可なら取得しない。`Crawl-delay` を優先。
- 同一ドメインへの連続アクセスは 10〜20 秒の不均一間隔、同時接続は1本。
- カルテは全記述に出典リンクを付与するプロンプト設計。
- SNS/ニュースメディアは現状スコープ外（TOS/API変動が大きいため）。

## 有料化前に設計へ追加予定（法務結論を反映して実装）

- カルテ出力プロンプトへ「**逐語転載禁止・自分の言葉で要約・引用は最小限＋出典明示**」を明文化（PoC段階では未実装＝保留中）。
- 生 Markdown をユーザーへそのまま見せない（再配信防止）出力ポリシー。
- 収集対象サイトの規約NG判定・オプトアウトの運用フロー。
